# AI Coding Guidelines for Angular-Go Compiler

When working on this project, the AI (Gemini or other assistants) MUST strictly adhere to the following rules:

1. **Strictly use the AST from typescript-go:** 
   You MUST leverage the AST (Abstract Syntax Tree) data structures and parsing logic provided by the `typescript-go` codebase. Do not reinvent the wheel.

2. **No Regex for Parsing:** 
   Parsing via Regular Expressions is STRICTLY PROHIBITED for any compiler logic. Always traverse and analyze the AST nodes to extract information, understand semantics, and generate code.

3. **1:1 Output Parity with @angular/compiler:**
   The compiled output (JavaScript/TypeScript/Metadata) generated by this Go-based compiler MUST be exactly identical (1:1 parity) to the output produced by the official `@angular/compiler` (written in TypeScript). We are porting the compiler to Go for performance, but the resulting artifacts must be completely indistinguishable from the official compiler.

4. **Continuous Comparison with `ngtsc`:**
   To ensure the 1:1 parity mentioned above, you MUST continuously compare the implementation and output of the new Go compiler with the original `@angular/compiler-cli/src/ngtsc` code (found in `angular-packages/angular-src`). Every feature, AST transformation, and generated string MUST be verified against how `ngtsc` does it. Do not guess the implementation; read the original `ngtsc` source code and port the logic faithfully.
